10 Exercícios Arrays vs. Listas Ponteiros & Memória Aplicações em Jogos

Comparação entre Arrays e Listas Ligadas Simples

01. Memória Contígua, Acesso e Cache

Explique a diferença entre como os dados são armazenados na memória RAM em um array e em uma lista encadeada simples. A partir disso, justifique por que:

  • acessar o elemento de índice 42 em um array tem custo imediato, enquanto na lista encadeada o acesso é sequencial;
  • processadores modernos conseguem otimizar melhor a leitura sequencial de um array do que a de uma lista encadeada.

02. Inserção e Redimensionamento

Suponha que um programa mantenha uma sequência ordenada de pontuações. Descreva o que acontece na memória ao inserir um novo elemento na 2ª posição nos três cenários abaixo, diferenciando o custo de encontrar a posição do custo de efetuar a inserção:

  • em um array de 100 posições com 60 elementos ocupados;
  • em um array alocado dinamicamente de 60 posições que já está completamente cheio;
  • em uma lista encadeada simples com 60 nós.

03. Consumo de Memória (Overhead vs. Desperdício)

Considere um registro de jogador composto por char nome[32] (32 bytes) e int pontos (4 bytes), em um sistema de 64 bits onde um ponteiro ocupa 8 bytes (desconsidere padding de alinhamento, ou indique-o como observação à parte).

  • Calcule o acréscimo de memória (overhead) por elemento ao usar uma lista encadeada simples em vez de um array.
  • Apresente um exemplo numérico de cenário em que um array de tamanho fixo ainda desperdiça mais RAM do que a lista encadeada.

Usos de Listas Ligadas Simples

04. Construção, Percurso e Liberação Segura em C

Modele em C uma struct RankingNode contendo char nome[32], int pontos e struct RankingNode *next. Implemente as três funções abaixo, garantindo verificação de falha na alocação (NULL) e ausência de memory leaks:

  • inserção de um novo jogador no início da lista;
  • percurso para imprimir todos os jogadores e suas pontuações no terminal;
  • free_lista, para liberar todos os nós da memória com segurança (explique em um comentário por que é necessário salvar next antes de chamar free).

05. Ordenação In-Place por Ponteiros (Insertion Sort)

Usando a struct RankingNode do exercício anterior, implemente uma função em C que ordene uma lista encadeada simples em ordem decrescente de pontuação utilizando o algoritmo Insertion Sort por religação de ponteiros (sem copiar nome e pontos de um nó para outro).

Em seguida, responda: qual é a vantagem de religar ponteiros em vez de trocar os dados internos quando a struct armazena muitos campos?

06. Remoção Condicional e Corte de Top-N

Para uma lista encadeada simples de jogadores (nome e pontos), implemente em C:

  • int remover_abaixo_de(RankingNode **head, int corte): remove e libera com free todos os nós cuja pontuação seja estritamente menor que corte, retornando quantos nós foram removidos (tratando corretamente o caso em que o primeiro nó é removido);
  • void manter_top_n(RankingNode **head, int n): assumindo que a lista já está ordenada de forma decrescente, mantém apenas os n primeiros registros, garante que o último nó mantido aponte para NULL e libera a memória dos nós excedentes.

Avanços: Listas Duplamente Encadeadas e Circulares

07. Lista Duplamente Encadeada e Remoção Direta

Crie em C uma struct DNode com ponteiros prev e next (além de um campo de dado inteiro ou texto).

  • Implemente a inserção no início atualizando corretamente next e prev.
  • Implemente void remover_no(DNode **head, DNode *alvo) capaz de remover e liberar o nó alvo recebendo apenas o ponteiro direto para ele, sem percorrer a lista desde o início.
  • Justifique por que essa mesma remoção em tempo constante (O(1)) não é possível recebendo apenas o ponteiro alvo em uma lista simplesmente encadeada.

08. Lista Encadeada Circular

Modele e implemente em C uma lista encadeada circular para representar um carrossel de opções (por exemplo, níveis de dificuldade FACIL, NORMAL, DIFICIL, INSANO), no qual o ponteiro next do último elemento aponta de volta para o primeiro.

  • Implemente funções para inserir um novo item, avançar para o próximo item e percorrer/imprimir todos os elementos exatamente uma vez, além de uma função free_circular para liberar toda a lista.
  • Explique qual condição de parada substitui atual != NULL nos laços de percurso e de liberação para evitar loops infinitos.

Listas Ligadas Aplicadas a Jogos

09. Gerenciador de Efeitos Temporários (Buffs e Debuffs)

Em jogos de ação e RPG, um personagem pode estar sob múltiplos efeitos simultâneos com durações diferentes (como escudo por 5 turnos, veneno por 3 turnos e velocidade extra por 2 turnos). Modele uma lista encadeada simples EfeitoNode contendo char nome[32], int turnos_restantes e struct EfeitoNode *next. Implemente uma função atualizar_efeitos que, a cada turno:

  • decrementa turnos_restantes de todos os efeitos ativos;
  • remove e libera com free automaticamente os efeitos que chegarem a 0, tratando corretamente o caso em que dois efeitos consecutivos — ou o primeiro da lista — expirem no mesmo turno.

10. Controle Dinâmico de Projéteis e Desempenho em Tempo Real

Em jogos 2D de tiro (como shoot 'em ups), projéteis são criados e destruídos constantemente na tela.

  • Modele uma lista encadeada simples de ProjetilNode (int x, int y, int dy, struct ProjetilNode *next) e implemente as funções criar_projetil (inserção) e atualizar_projeteis (soma dy à posição y de cada projétil e remove/libera com free aqueles que saírem do intervalo válido 0 <= y < altura_tela).
  • Escreva um parágrafo explicando por que motores de jogos comerciais costumam evitar chamadas frequentes de malloc/calloc e free dentro do loop principal (30 ou 60 FPS), mesmo quando usam listas encadeadas para organizar entidades ativas (por exemplo, combinando ponteiros de lista com pools de memória pré-alocada).
